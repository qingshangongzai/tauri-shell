# 安装/卸载向导说明（installer/ 子包）

轻壳自带的 Windows 安装器/卸载器，代码位于仓库 `installer/` 子包，
用 **Tauri 2 + React + Tailwind 4** 实现：安装向导 UI 自绘，
注册表写入与控制面板集成行为对齐 NSIS。
仓库根执行 `npm run build` 即产出单文件安装器，无需单独操作该子包；
不需要自定义向导时也可用 `npm run build:nsis` 走 Tauri 官方 NSIS 打包（两者并存）。

> 本文中的相对路径均以仓库根为基准。

## 功能特性

- **安装向导**：欢迎 → 路径选择 → 选项（快捷方式/文件关联）→ 进度 → 完成，左侧步骤导航，亮/暗主题跟随系统
- **卸载向导**：同一个 exe 通过 `--uninstall` 参数分流，UI 风格与安装向导一致；控制面板"卸载"即走此路径
- **双路径安装**：系统级（`C:\Program Files` + HKLM，按需 UAC 提权）/ 用户级（`%LOCALAPPDATA%\Programs` + HKCU，免提权）
- **按需 UAC 提权**：exe 为 `asInvoker` manifest，仅在系统级安装/卸载时启动提权子进程；向导 UI 保持存活，通过进度文件轮询转发进度
- **控制面板集成**：写入标准 Uninstall 注册表键（DisplayName/UninstallString/EstimatedSize 等）
- **快捷方式**：COM `IShellLinkW` 创建开始菜单/桌面 `.lnk`
- **文件关联（可选，默认关闭）**：ProgID + Applications + Capabilities 完整登记面，让应用进入"打开方式/默认应用"候选；不强改扩展名默认值（Win10/11 UserChoice 机制下强改无效且属劫持行为）
- **主程序包嵌入**：主应用产物压缩为 zip 后 `include_bytes!` 嵌入安装器，单文件分发；解压防 zip-slip
- **卸载器体积优化**：双产物构建——先编译不含 zip 的"纯壳"打进 bundle 作为卸载器，再编译嵌入 zip 的完整安装器
- **健壮性**：安装/卸载前枚举并关闭安装目录下运行中的进程；卸载器位于安装目录内时自复制到 `%TEMP%` 重启以便删除自身
- **自动化测试**：30+ 个 Rust 测试覆盖注册表、快捷方式、安装/卸载编排（测试仅写 HKCU 专用键与 `%TEMP%`，不污染真实环境）

## 模板改名清单

产品信息集中在两个配置文件，其余代码无需触碰：

| 文件 | 内容 |
|---|---|
| `installer/src-tauri/src/config.rs` | Rust 侧全部产品常量（显示名、exe 名、注册表键、文件关联等，逐项有注释） |
| `installer/src/product.ts` | 前端文案（产品名、文件关联开关文案，须与 config.rs 一致） |

另有三处常规配置：

- `installer/src-tauri/tauri.conf.json`：`productName` / `identifier` / 窗口 `title`
- `installer/src-tauri/Cargo.toml`：`[[bin]] name`（= config.rs 的 `WIZARD_EXE_NAME` 去掉 `.exe`）与 `[package.metadata.tauri-winres]`
- `installer/index.html`：`<title>`

图标与页面 logo 无需在子包维护：主项目构建时 `scripts/gen-icons.mjs` 会从唯一源图
`src-tauri/icons/logo.svg` 生成并自动同步子包的 `installer/src-tauri/icons/icon.ico`
（安装器 EXE 图标）与 `installer/public/logo.svg`（向导页面 logo），两处文件勿手改。
版本号由仓库根 `sync-version.cjs` 自动同步，同样勿手改。

### 启用文件关联

1. `installer/src-tauri/src/config.rs`：`ASSOC_EXTENSIONS` 填入扩展名（如 `&["md", "markdown"]`），并按需调整 `PROGID` 等关联常量
2. `installer/src/product.ts`：`FILE_ASSOC_ENABLED` 改为 `true`，调整开关文案

## 运行模式（同一个 exe，参数分流）

| 启动参数 | 模式 |
|---|---|
| （无参数） | 安装向导 UI |
| `--uninstall` | 卸载向导 UI（UninstallString 走此路径） |
| `--uninstall --confirm [--detected-*] [--remove-user-data]` | 无头卸载（提权 worker / CLI） |
| `--elevated --install-path="..." [--desktop-shortcut] [--file-assoc] --progress-file="..."` | 提权安装 worker（UAC 后由安装器自身启动） |

## 构建流程（scripts/build-installer.mjs，五步双产物）

```
1. 构建主应用            npm run tauri -- build --no-bundle → 主程序 exe
                         （beforeBuildCommand 顺带完成图标生成与同步）
2. 编译"纯壳"            删残留 zip → vite build → 第一次 cargo build
                         （build.rs 零字节占位机制生效，产出不含 zip 的壳 = 卸载器）
3. 打 bundle zip         主程序 exe + 纯壳 → Compress-Archive → app-bundle.zip（仓库根）
4. 编译完整安装器         第二次 cargo build（参数与第一次完全一致）嵌入 zip
5. 收集产物              dist-installer/{产品名}_{版本}_x64-setup.exe + 体积校验
```

耗时说明：首次打包需完整编译安装器依赖（数分钟）；后续增量构建仅重编
安装器自身 crate。只改安装器、主应用未变时可加 `--skip-main` 跳过第 1 步：

```bash
npm run build -- --skip-main
```

关键坑：

- **不要用 `tauri build` 编译安装器**——它会按 productName 重命名二进制；直接 `cargo build --release --features tauri/custom-protocol`。`custom-protocol` feature 必须显式开启，否则 release 产物仍加载 devUrl（白屏）
- 两次 cargo build 参数必须完全一致，否则 Cargo 视为不同配置大面积重编
- zip 用 deflate（PowerShell `Compress-Archive` 与 `zip` crate 的 deflate feature 兼容）
- 体积校验：完整安装器必须 > zip 体积（防零字节占位）且 > 纯壳体积（防第二次编译未重新嵌入）
- release profile 的 `lto` 用 `"thin"` 而非全量：双产物流程每次要链接两次，全量 LTO 会让每次打包多花 2 分钟以上，体积收益仅几百 KB

## 开发与测试

```bash
# 安装依赖（首次打包时构建脚本也会自动安装）
npm --prefix installer install

# 向导 UI 开发预览（仓库根执行；无嵌入包时进度页会报"安装包未嵌入"，属预期）
npm run dev:installer

# 前端类型检查
npm --prefix installer run typecheck

# Rust 测试（仅写 HKCU 测试专用键与 %TEMP%，安全）
cd installer/src-tauri && cargo test

# 完整打包（仓库根执行）
npm run build
```

## 环境要求与已知限制

- **仅支持 Windows**（Win10/11）；非 Windows 平台编译通过但所有安装命令不可用
- 依赖：Rust（stable）、Node 18+、Tauri 2、WebView2（Win10/11 预装）
- **无法程序化"设为默认应用"**：Win10/11 的 UserChoice 哈希由 Explorer 校验，程序写入被判定为劫持；本安装器只做登记 + 深链引导用户在系统设置中完成
- 产物未签名时可能被 Defender SmartScreen 提示（与 NSIS 产物一致）；双产物方案下纯壳可先独立签名再打入 bundle
- 主要 Rust 依赖：`windows` 0.61（Win32 API）、`winreg` 0.52、`zip` 2（deflate）、`serde`/`serde_json`
