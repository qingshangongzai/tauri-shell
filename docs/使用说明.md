# 使用说明

轻壳有两条使用路径，按你的需求选择其一：

- **路径 ①「纯壳」** — 已有自己的网页，只想把它打包成 Windows 桌面程序。
- **路径 ②「同风格开发」** — 认可示例页的「去线留白」风格，想在这套设计语言与组件的基础上开发自己的应用。

> 设计语言的完整定义见 [“去线留白”设计语言.md](./“去线留白”设计语言.md)；云构建、安装器与托盘的专题说明见本文末尾的[「云构建」](#云构建github-actions)、[「安装/卸载向导」](#安装卸载向导installer-子包)与[「系统托盘」](#系统托盘)三章。

## 路径 ①：纯壳 — 打包你自己的 HTML

### 1. 替换页面

把你的网页内容写进 `dist/index.html`（单文件；如有额外静态资源需同时在 `minify.cjs` 的白名单中登记，见下方「构建产物白名单」）。

### 2. 标题栏：壳自动适配，无需配置

壳在页面加载完成后自动判定边框模式（判定与切换发生在窗口显示前，无跳变）：

- HTML 中存在 `data-tauri-drag-region` 属性（即自绘标题栏的拖拽区） → **无边框窗口**，由你的标题栏接管拖拽与三键；
- 不存在 → 自动切回 **系统原生标题栏**，拖拽、最小化/最大化/关闭全部由系统提供。

所以把任意能在浏览器里跑的 HTML 丢进 `dist/index.html` 即可，**不需要保留示例页的任何代码，也不需要改配置**。想得到无边框窗口，同样**不需要整套 UI 框架**——唯一要做的是让页面自带一条标题栏，完整代码见下。

> 本节自包含：**把本文档（可连同「去线留白」设计语言文档）直接发给 AI**，请它“按文档生成一个无边框的 HTML 页面”，AI 即可据此产出符合壳规范的页面，无需任何其他文件。

#### 无边框窗口 = 三件事

1. **拖拽区**：一个元素带 `data-tauri-drag-region` 属性——加在标题栏上，壳靠它识别“这是无边框页面”，Tauri 靠它实现拖拽。
2. **三个窗口按钮**：最小化 / 最大化 / 关闭，放在标题栏右侧。
3. **一小段 JS**：把三个按钮接到窗口命令上。单文件页面用 `window.__TAURI_INTERNALS__.invoke(...)` 直调，**无需 npm 打包**；用 React/Vue 等框架构建的页面也可用 `@tauri-apps/api/window` 的 `getCurrentWindow().minimize()` 等，效果相同。

#### 最小完整示例（直接抄）

标题栏放在 `<body>` 最前面（页面其他内容照常写在后面即可）：

```html
<body>
    <div class="titlebar" data-tauri-drag-region>
        <span class="titlebar-title">我的应用</span>
        <div class="window-controls">
            <button class="win-btn" id="winMin" aria-label="最小化"></button>
            <button class="win-btn" id="winMax" aria-label="最大化"></button>
            <button class="win-btn win-btn-close" id="winClose" aria-label="关闭"></button>
        </div>
    </div>
    <main class="content">
        <!-- 你的页面内容写在这里 -->
    </main>
</body>
```

CSS（写死颜色的最小版；引入「去线留白」设计令牌后换成令牌，见文末说明）：

```css
body { margin: 0; height: 100vh; overflow: hidden; }   /* 页面自身不滚动：滚动交给内容区，否则滚动条会贯穿到标题栏 */

/* 标题栏 */
.titlebar {
    position: fixed; top: 0; left: 0; right: 0;
    height: 40px;
    display: flex; align-items: center;
    padding-left: 16px;
    background: #f6f6f6;
    -webkit-user-select: none;   /* 拖拽时禁止选中文字 */
    user-select: none;
    z-index: 1000;
}
.titlebar-title {
    font-size: 13px;
    font-weight: 600;
    pointer-events: none;        /* 关键：点击穿透到拖拽区，标题文字上也能拖 */
}
.window-controls { position: absolute; right: 0; top: 0; bottom: 0; display: flex; }
.win-btn {
    width: 46px;
    border: none;
    background: transparent;
    color: #444;
    cursor: default;
    display: flex; align-items: center; justify-content: center;
}
.win-btn:hover { background: rgba(0, 0, 0, .06); }
.win-btn-close:hover { background: #e81123; color: #fff; }

/* 三个按钮的图标：最小化横线、最大化方框、关闭叉号 */
.win-btn-min::after { content: ''; width: 10px; height: 1.5px; background: currentColor; border-radius: 1px; }
.win-btn-max::after { content: ''; width: 10px; height: 10px; border: 1.5px solid currentColor; border-radius: 1px; box-sizing: border-box; }
.win-btn-close::after { content: '✕'; }

/* 页面内容：标题栏下方的独立滚动区——滚动条从标题栏下方开始，不会顶到标题栏 */
.content {
    height: calc(100vh - 40px);
    margin-top: 40px;
    overflow-y: auto;
}
```

JS（放在 `<body>` 末尾）：

```html
<script>
    const tauri = window.__TAURI_INTERNALS__;
    if (tauri) {
        // Tauri 环境：三个按钮接到窗口命令（权限壳已全部开放，无需改配置）
        const invoke = cmd => tauri.invoke(cmd);
        document.getElementById('winMin').addEventListener('click', () => invoke('plugin:window|minimize'));
        document.getElementById('winMax').addEventListener('click', () => invoke('plugin:window|toggle_maximize'));
        // 关闭：默认最小化到托盘（托盘左键还原、右键菜单退出）；
        // 已按本文末尾「按需移除托盘」移除托盘时（exit_app 命令随之删除），改为 invoke('plugin:window|close')
        document.getElementById('winClose').addEventListener('click', () => invoke('plugin:window|hide'));
    } else {
        // 浏览器里直接打开预览：没有窗口可控制，隐藏标题栏
        document.querySelector('.titlebar').style.display = 'none';
    }
</script>
```

> 深色模式：引入设计令牌后，把 `#f6f6f6`、`#444`、hover 的 `rgba(0,0,0,.06)` 分别换成 `var(--titlebar)`、`var(--text-body)`、`var(--hover)`，关闭红底用 `var(--close-hover)` + `var(--static-white)`，标题栏即自动适配深浅主题（令牌清单见路径 ②「设计令牌速查」）。

#### 各部分在做什么（AI 生成页面也按此规范）

- **拖拽规则**：`data-tauri-drag-region`（裸属性）= 只有**直接按在该元素上**的左键拖动生效；标题栏里的按钮等可点击元素天然不触发拖拽（Tauri 内置规则），无需额外处理。想让整块区域任意位置都能拖，改用 `data-tauri-drag-region="deep"`。
- **双击拖拽区 = 最大化/还原**：Tauri 内置行为，无需写 JS。
- **命令与权限**：示例用到的窗口命令（`minimize` / `toggle_maximize` / `hide` / `is_maximized`）以及拖拽所需的 `start-dragging` 权限，都已在 `src-tauri/capabilities/default.json` 开放——**生成页面时不需要动任何配置**。
- **关闭按钮与托盘**：壳默认「关闭 → 最小化到托盘」（托盘左键还原、右键菜单退出），故示例用 `plugin:window|hide`；移除托盘后改 `plugin:window|close`（届时已无其他窗口拖住进程，窗口销毁即退出）。挂托盘时**不要用** `plugin:window|close`（主窗口销毁后托盘无法还原，进程成僵尸）。原生标题栏下的 X 同理默认最小化到托盘，希望直接退出按[「按需移除托盘」](#按需移除托盘)操作。
- **浏览器预览**：纯浏览器里 `window.__TAURI_INTERNALS__` 不存在（示例会隐藏标题栏），拖拽与三键不可用属正常——浏览器没有“窗口”概念，请用 `npm run tauri dev` 或打包后验证。
- **窗口显示**：显示时机由壳统一负责（检测完成后显示，另有 2 秒超时兜底），页面无需调用 `plugin:window|show`。
- **滚动区域**：`body` 自身不滚动（`overflow: hidden`），滚动交给 `.content`——若让 body 滚动，滚动条会贯穿整个视口、从标题栏右侧一路到底；滚动条样式定制见下方「可选优化：细窄滚动条」。

#### 可选优化：最大化按钮的还原态

最大化后把方框图标换成“还原”（查询 `is_maximized` + 监听窗口 resize；加在主脚本 `if (tauri)` 分支内）：

```js
const maxBtn = document.getElementById('winMax');
const updateMaxBtn = async () => {
    const maximized = await invoke('plugin:window|is_maximized');
    maxBtn.classList.toggle('maximized', maximized);
    maxBtn.title = maximized ? '还原' : '最大化';
};
window.addEventListener('resize', updateMaxBtn);
updateMaxBtn();
```

配合 CSS（经典 Windows 双层方块图标）：

```css
.win-btn.maximized { position: relative; }
.win-btn.maximized::after { width: 8px; height: 8px; transform: translate(-1px, 1px); }
.win-btn.maximized::before {
    content: '';
    position: absolute;
    left: 50%; top: 50%;
    width: 8px; height: 8px;
    border-top: 1.5px solid currentColor;
    border-right: 1.5px solid currentColor;
    border-top-right-radius: 2px;
    box-sizing: border-box;
    transform: translate(calc(-50% + 2px), calc(-50% - 2px));
}
```

#### 可选优化：细窄滚动条

默认滚动条较粗，且与「去线留白」风格不搭，可定制为细窄圆角样式（WebView2 基于 Chromium，支持 `::-webkit-scrollbar` 伪元素；示例页同款）：

```css
.content::-webkit-scrollbar { width: 6px; }
.content::-webkit-scrollbar-track { background: transparent; }
.content::-webkit-scrollbar-thumb { background: var(--divider, rgba(0, 0, 0, .15)); border-radius: 3px; }
```

> 滚动条始终跟随它的滚动容器：只要按主示例把滚动限制在 `.content`（body 不滚动），滚动条就从标题栏下方开始、不会顶到标题栏；若让 body 直接滚动，滚动条会贯穿整个视口，从标题栏右侧一路延伸到窗口底部。引入设计令牌后 `--divider` 会自动适配深浅主题，无需额外处理。

#### 两个容易踩的坑

- **不要用 `-webkit-app-region: drag`**：WebView2 会把它按系统非客户区标题栏处理，右键时在引擎层直接弹出 Windows 系统菜单，顶层窗口侧无法拦截；拖拽统一走 `data-tauri-drag-region`（JS 通道，仅响应左键）。
- **自绘标题栏需写在初始 HTML 里**：React/Vue 等运行时才渲染出 `data-tauri-drag-region` 的页面可能漏判为原生标题栏；此类页面可在渲染完成后自行调用 `getCurrentWindow().setDecorations(false)`（`@tauri-apps/api/window`）覆盖。反向覆盖同理：有拖拽区但就想要原生框，删掉 `data-tauri-drag-region` 属性即可。（壳已在 `capabilities/default.json` 开放 `core:window:allow-set-decorations` 权限。）

> **参考**：无边框窗口本身用本节的最小方案即可实现，无需其他文件；想要示例页同款的**整套 UI 框架**（侧边栏、页面切换、深色模式、组件库等），再以 `components/starter.html` 为底，把你的内容填进页面区即可——完整流程见路径 ②「starter.html 上手流程」。
>
> **也可以直接把 `components/starter.html` 发给 AI**：模板自带合规的无边框标题栏与整套骨架，AI 只需保留标题栏与窗口控制脚本不动、按注释「加页面三步」往页面区填内容，即可得到同风格的无边框应用，同样不需要改任何配置。只想做无边框的裸页面、风格自由发挥的，则按本节开头把本文档发给 AI。

### 4. 构建命令速查

| 命令 | 产物 |
|------|------|
| `npm run tauri dev` | 开发预览，改 `dist/index.html` 自动刷新 |
| `npm run build` | 自带安装向导的单文件安装包（`dist-installer/`） |
| `npm run build -- --skip-main` | 只重打安装器，跳过主应用构建 |
| `npm run build:nsis` | NSIS 安装包（`src-tauri/target/release/bundle/nsis/`） |
| `npm run tauri build -- --no-bundle` | 裸 EXE（`src-tauri/target/release/`） |
| `cargo clean`（在 `src-tauri/` 下运行） | 清除 Rust 编译缓存（`target/`），释放磁盘空间 |

> 💡 `target/` 是 Rust 编译中间产物目录，一次完整构建可占用数 GB 磁盘（安装器子包还有 `installer/src-tauri/target`）。若只是偶尔打包一次，可进入 `src-tauri/` 运行 `cargo clean` 清除；下次构建将从零全量编译，耗时明显变长。

> 本地没有 Rust / Node 环境？可以用 GitHub Actions 云端打包，全程在网页上操作，见本文末尾[「云构建」](#云构建github-actions)章。

### 5. 右键菜单：屏蔽 WebView2 默认菜单

打包后的应用里右键，会弹出 WebView2（Edge 内核）的**默认菜单**（前进/后退、刷新、查看源代码、打印等）——因为页面没有拦它。WebView2 基于 Chromium，行为与浏览器一致：**页面取消了 `contextmenu` 事件，引擎就不弹默认菜单**。因此屏蔽它不需要改任何配置或 Rust 代码，纯页面 JS 即可；网页里已有的自绘右键菜单（同样调用了 `preventDefault`）在壳内照常生效，无需额外处理。

只想屏蔽（不替换）：

```html
<script>
    // 屏蔽 WebView2 默认右键菜单（浏览器里预览同样生效）
    document.addEventListener('contextmenu', e => e.preventDefault());
</script>
```

只屏蔽后右键毫无反馈，用户会以为右键失效；更常见的做法是屏蔽 + 在光标处弹应用风格的自绘菜单。示例页与 `components/context-menu.html` demo 即此实现（全局 `contextmenu` 监听 → `preventDefault()` → 弹 `.context-menu`，含复制/粘贴置灰逻辑、键盘导航、外点关闭），复制指引见路径 ② 组件表「右键菜单」行。屏蔽默认菜单后注意两点：

- 输入框右键的“粘贴 / 剪切”等默认项也没了，需要自绘菜单提供（示例页菜单已实现）；
- 键盘快捷键不受影响：Ctrl+C / Ctrl+V 等照常可用。

### 构建产物白名单

打包只收录 `dist-min/` 下的文件，由 `minify.cjs` 白名单式生成：默认仅 `index.html`、`tray-menu.html` 两页 + `logo.svg`。若你的页面引用了其他静态资源，需在 `minify.cjs` 中补充拷贝；`components/` 目录仅是参考资料，**不进任何构建产物**。

### 同步约定（重要）

`dist/index.html` 是**唯一权威源**（活体演示），`components/` 内是手动拆分的拷贝。两侧对应分节都写有「已拆出 / 拷贝自 …，改动请同步」注释——改任何一侧组件代码时，请把改动同步到另一侧。设计令牌则是三处同源：`dist/index.html`、`installer/src/styles/tokens.css`、`components/tokens.css`。

### 设计令牌速查

深色模式机制：所有令牌在 `[data-theme="dark"]` 下整体反转，JS 只需切换 `<html>` 的 `data-theme` 属性。

| 类别 | 令牌 | 用途 |
|------|------|------|
| 画布/表面 | `--bg` / `--sidebar` / `--card` / `--titlebar` | 页面底、侧栏、卡片、标题栏底色 |
| 交互底色 | `--hover` / `--divider` / `--input-bg` / `--input-bg-focus` | 悬停、按压、填充式输入框 |
| 强调色 | `--accent` / `--accent-bg` / `--accent-hover` / `--on-accent` | 主按钮、选中态、链接 |
| 语义色 | `--danger(-bg)` / `--warning(-bg)` / `--copy-success` | 错误、警告、成功 |
| 文字阶梯 | `--text-primary` (87%) / `--text-body` (78%) / `--text-auxiliary` (52%) / `--text-placeholder` (30%) | 用不透明度而非灰阶表达层级 |
| 动效 | `--ease` / `--duration-fast` (100ms) / `--duration-normal` (200ms) / `--duration-slow` (300ms) | 统一缓动与时长；已带 `prefers-reduced-motion` 降级 |
| 层级阴影 | `--shadow-card`（静置卡片）/ `--shadow-flyout`（浮层） | 弥散阴影代替边框线表达 elevation |
| 几何/字体 | `--radius` (10px) / `--radius-sm` (6px) / `--font` | 圆角与衬线字体 |

核心原则「去线留白」：不用边框线，用**留白、色块、弥散阴影**表达分隔与层级。新写的界面只要坚持从令牌取值、不写死颜色，即可自动获得深色模式与整体一致性。

## 示例页多语言（i18n）机制

示例页内置简体中文 / English / 日本語三语切换（设置页「语言」下拉，选后即时生效并持久化到 localStorage 键 `tauri-shell-lang`）。零依赖字典方案，全部代码内联在 `dist/index.html` 脚本区的「多语言（i18n）」分节：

- **字典** `I18N`：`{ 'zh-CN': {...}, 'en': {...}, 'ja': {...} }`，语义化键名（如 `nav.dashboard`）；HTML 中的中文原文即兜底，键缺失时回退 zh-CN、再缺失则保持现状不报错。
- **静态文案**：元素加 `data-i18n="键名"`（替换 textContent）或 `data-i18n-html`（含内联标签时）；属性文案用 `data-i18n-attr="placeholder:键名;aria-label:键名2"` 声明。
- **动态字符串**：JS 中统一走 `t('键名', { n: 值 })` 取词，支持 `{n}` 占位符；切语言时广播 `app-localechange` 事件，需要重绘的动态模块（如 Select 演示、在线状态）监听它刷新。
- **增删词条**：三语字典同步增删同名键即可；**新增语言**：在 `I18N` 补一份完整字典 + 设置页语言下拉加一项；**移除 i18n**：删掉该分节与语言下拉即可，页面回退为纯中文。
- **托盘菜单** `dist/tray-menu.html` 另有一份内联小字典 `TRAY_I18N`（仅两菜单项），与主窗口共享同一 localStorage 键，每次弹出时重读并按文案重测窗口尺寸。
- 品牌与专名不译：应用名「轻壳」、Tauri、快捷键 kbd 键名保持原文；选项 label 用各语言自称（native name）。

> `components/*.html` 与 `starter.html` 是中文参考资料，不包含 i18n；路径 ① 替换整页后此机制随示例页一同被替换，无需额外处理。

## 云构建（GitHub Actions）

不想在本地安装 Rust / Node 工具链？可以把打包工作交给 GitHub Actions：你只需要在 GitHub 网页上编辑文件、打一个标签，云端就会自动构建出安装包放进 Release。页面本身用浏览器调试（双击 HTML 文件即可），仅打包成 EXE 交给云端，全程本地零环境。

> 仓库自带工作流文件 [.github/workflows/release.yml](../.github/workflows/release.yml)，无需自己编写。

### 前提

- 一个 GitHub 账号，且网络可正常访问 GitHub。
- 本项目主仓库在 Gitee；若你从 Gitee 获取的代码，请使用它在 GitHub 上的镜像仓库操作（或自己把代码推到 GitHub 新仓库——注意推送包含 `.github/workflows/` 的提交时，所用 token 需勾选 `workflow` 权限，Gitee 镜像同步到 GitHub 时同理）。

### 步骤

1. **Fork 仓库**：打开 GitHub 上的仓库页面，点右上角 **Fork** 得到一份副本。
2. **网页端替换页面**：在你 fork 的仓库里打开 `dist/index.html`，点编辑按钮（铅笔图标），把内容整体替换为你自己的网页，提交（Commit changes）。不需要保留原文件任何代码（标题栏与窗口显示自动适配，见上方「标题栏」小节）；只想试效果只改这一个文件就够了，改应用名/图标见上方「改名清单」。
3. **触发构建（二选一）**：
   - **方式 A—打标签发 Release**（推荐，产物任何人可下载）：（可选）先把 `src-tauri/tauri.conf.json` 的 `version` 改成目标版本号 → 仓库主页右侧 **Releases** → **Create a new release** → Tag 填 `v` 开头的版本（如 `v0.1.0`，选 Create new tag）→ **Publish release**；构建完成后安装包 `{产品名}_{版本}_x64-setup.exe` 自动附到该 Release 的 Assets。
   - **方式 B—手动运行**（产物为 Artifact，需登录 GitHub 下载）：仓库页面 → **Actions** → 左侧选「构建安装包」→ **Run workflow**，完成后在该次运行页面的 **Artifacts** 区下载。（首次 fork 后 Actions 可能默认停用，进 Actions 页面点一次启用即可。）
4. **下载安装**：从 Release Assets（或 Artifact）下载 exe，双击即进入安装向导。

### 常见问题

- **构建要多久？** 首次构建无缓存，需完整编译两个 Rust 项目，约 15~25 分钟；之后有缓存会明显加快。
- **Windows 提示「已保护你的电脑」（SmartScreen）？** 产物未做代码签名，本地构建也是同样结果，与云构建无关。点「更多信息 → 仍要运行」即可；正式分发建议购买代码签名证书。
- **Actions 免费吗？** 公开（public）仓库免费不限时长；私有仓库有每月免费额度（Windows runner 按 2 倍计费），超出需付费。
- **还能实时预览吗？** `npm run tauri dev` 的实时预览仍需本地环境。但纯 HTML 页面直接用浏览器打开调试即可，仅窗口控制、托盘、文件拖放与大小获取等 Tauri 能力需要在壳内验证。
- **页面引用了额外的图片 / CSS / JS 文件？** 构建只收录白名单内的文件，需在 `minify.cjs` 中登记（见上方「构建产物白名单」）；最省事的做法是把资源内联进单个 `index.html`。

## 安装/卸载向导（installer/ 子包）

轻壳自带的 Windows 安装器/卸载器，代码位于仓库 `installer/` 子包，
用 **Tauri 2 + React + Tailwind 4** 实现：安装向导 UI 自绘，
注册表写入与控制面板集成行为对齐 NSIS。
仓库根执行 `npm run build` 即产出单文件安装器，无需单独操作该子包；
不需要自定义向导时也可用 `npm run build:nsis` 走 Tauri 官方 NSIS 打包（两者并存）。

### 功能特性

- **安装向导**：欢迎 → 路径选择 → 选项（快捷方式/文件关联）→ 进度 → 完成，左侧步骤导航，亮/暗主题跟随系统
- **卸载向导**：同一个 exe 通过 `--uninstall` 参数分流，UI 风格与安装向导一致；控制面板“卸载”即走此路径
- **双路径安装**：系统级（`C:\Program Files` + HKLM，按需 UAC 提权）/ 用户级（`%LOCALAPPDATA%\Programs` + HKCU，免提权）
- **按需 UAC 提权**：exe 为 `asInvoker` manifest，仅在系统级安装/卸载时启动提权子进程；向导 UI 保持存活，通过进度文件轮询转发进度
- **控制面板集成**：写入标准 Uninstall 注册表键（DisplayName/UninstallString/EstimatedSize 等）
- **快捷方式**：COM `IShellLinkW` 创建开始菜单/桌面 `.lnk`
- **文件关联（可选，默认关闭）**：ProgID + Applications + Capabilities 完整登记面，让应用进入“打开方式/默认应用”候选；不强改扩展名默认值（Win10/11 UserChoice 机制下强改无效且属劫持行为）
- **主程序包嵌入**：主应用产物压缩为 zip 后 `include_bytes!` 嵌入安装器，单文件分发；解压防 zip-slip
- **卸载器体积优化**：双产物构建——先编译不含 zip 的“纯壳”打进 bundle 作为卸载器，再编译嵌入 zip 的完整安装器
- **健壮性**：安装/卸载前枚举并关闭安装目录下运行中的进程；卸载器位于安装目录内时自复制到 `%TEMP%` 重启以便删除自身
- **自动化测试**：30+ 个 Rust 测试覆盖注册表、快捷方式、安装/卸载编排（测试仅写 HKCU 专用键与 `%TEMP%`，不污染真实环境）

### 模板改名清单

产品信息集中在两个配置文件，其余代码无需触碰：

| 文件 | 内容 |
|---|---|
| `installer/src-tauri/src/config.rs` | Rust 侧全部产品常量（显示名、exe 名、注册表键、文件关联等，逐项有注释） |
| `installer/src/product.ts` | 前端文案（产品名、文件关联开关文案，须与 config.rs 一致） |

另有三处常规配置：

- `installer/src-tauri/tauri.conf.json`：`productName` / `identifier` / 窗口 `title`
- `installer/src-tauri/Cargo.toml`：`[[bin]] name`（= config.rs 的 `WIZARD_EXE_NAME` 去掉 `.exe`）与 `[package.metadata.tauri-winres]`
- `installer/index.html`：`<title>`

图标与页面 logo 无需在子包维护：主项目构建时 `scripts/gen-icons.mjs` 会从唯一源图
`src-tauri/icons/logo.svg` 生成并自动同步子包的 `installer/src-tauri/icons/icon.ico`

#### 启用文件关联

2. `installer/src/product.ts`：`FILE_ASSOC_ENABLED` 改为 `true`，调整开关文案

### 运行模式（同一个 exe，参数分流）

| 启动参数 | 模式 |
|---|---|
| （无参数） | 安装向导 UI |
| `--uninstall` | 卸载向导 UI（UninstallString 走此路径） |
| `--uninstall --confirm [--detected-*] [--remove-user-data]` | 无头卸载（提权 worker / CLI） |
| `--elevated --install-path="..." [--desktop-shortcut] [--file-assoc] --progress-file="..."` | 提权安装 worker（UAC 后由安装器自身启动） |

### 构建流程（scripts/build-installer.mjs，五步双产物）

```
1. 构建主应用            npm run tauri -- build --no-bundle → 主程序 exe
                         （beforeBuildCommand 顺带完成图标生成与同步）
2. 编译"纯壳"            删残留 zip → vite build → 第一次 cargo build
                         （build.rs 零字节占位机制生效，产出不含 zip 的壳 = 卸载器）
3. 打 bundle zip         主程序 exe + 纯壳 → Compress-Archive → app-bundle.zip（仓库根）
4. 编译完整安装器         第二次 cargo build（参数与第一次完全一致）嵌入 zip
5. 收集产物              dist-installer/{产品名}_{版本}_x64-setup.exe + 体积校验
```

耗时说明：首次打包需完整编译安装器依赖（数分钟）；后续增量构建仅重编
安装器自身 crate。只改安装器、主应用未变时可加 `--skip-main` 跳过第 1 步：

```bash
npm run build -- --skip-main
```

关键坑：

- **不要用 `tauri build` 编译安装器**——它会按 productName 重命名二进制；直接 `cargo build --release --features tauri/custom-protocol`。`custom-protocol` feature 必须显式开启，否则 release 产物仍加载 devUrl（白屏）
- 两次 cargo build 参数必须完全一致，否则 Cargo 视为不同配置大面积重编
- zip 用 deflate（PowerShell `Compress-Archive` 与 `zip` crate 的 deflate feature 兼容）
- 体积校验：完整安装器必须 > zip 体积（防零字节占位）且 > 纯壳体积（防第二次编译未重新嵌入）
- release profile 的 `lto` 用 `"thin"` 而非全量：双产物流程每次要链接两次，全量 LTO 会让每次打包多花 2 分钟以上，体积收益仅几百 KB

### 环境要求与已知限制

- **仅支持 Windows**（Win10/11）；非 Windows 平台编译通过但所有安装命令不可用
- 依赖：Rust（stable）、Node 18+、Tauri 2、WebView2（Win10/11 预装）

- 主要 Rust 依赖：`windows` 0.61（Win32 API）、`winreg` 0.52、`zip` 2（deflate）、`serde`/`serde_json`

## 系统托盘

轻壳内置的系统托盘能力：关闭窗口最小化到托盘（设置页可关）、托盘左键还原主窗口、
右键弹出与应用同风格的**自绘菜单**。托盘是少数需要动 Rust 代码的能力
（与 `get_file_size` 同在 `lib.rs`），不需要时可按本章末尾步骤完整移除。

### 为什么自绘菜单

Tauri 原生托盘菜单（muda → Win32）的背景、间距、圆角、悬浮色均不可控，
无法与「去线留白」的应用内右键菜单对齐。因此托盘图标不挂原生 `.menu()`，
右键时在光标处弹出一个**预建的透明无边框 Webview 小窗**（`tray-menu`）渲染 Web 菜单，
视觉与应用内 `.context-menu` 像素级一致。

### 涉及文件

| 文件 | 作用 |
|---|---|
| `dist/tray-menu.html` | 菜单页面（自包含：令牌子集 + 菜单样式 + 交互脚本） |
| `src-tauri/src/lib.rs` | 「托盘」注释块：`exit_app` / `show_main_window` 命令、`position_menu_window` 定位、`.setup()` 内托盘注册、失焦隐藏与主窗口 `CloseRequested` 拦截（原生 X → 隐藏进托盘） |
| `src-tauri/tauri.conf.json` | `app.windows` 中 `label: "tray-menu"` 的窗口（透明/无边框/置顶/skipTaskbar/初始隐藏） |
| `src-tauri/capabilities/tray-menu.json` | 菜单窗口最小权限（hide + set-size） |
| `src-tauri/capabilities/default.json` | 主窗口的 `core:window:allow-hide`（关闭 → 隐藏到托盘） |
| `src-tauri/Cargo.toml` | tauri 依赖的 `"tray-icon"` feature |
| `dist/serve.json` | dev 静态服务器关闭 cleanUrls（见下方「易踩坑」） |
| `minify.cjs` | `PAGES` 数组包含 `tray-menu.html`，构建时一并压缩进 `dist-min/` |

### 工作流程

- **右键托盘**：Rust 收到 `TrayIconEvent::Click`（Right + Up）→ `position_menu_window`
  按光标物理坐标定位（可见卡片左下角贴光标、向右上展开，`monitor_from_point` 夹取防出屏）
  → `show()` + `set_focus()` 显示预建窗口
- **菜单项点击**：`tray-menu.html` 通过 `__TAURI_INTERNALS__.invoke` 直调 Rust 命令——
  「打开主界面」→ `show_main_window` 后自隐藏；「退出」→ `exit_app`
- **菜单收起**：失焦（Rust 侧 `Focused(false)` → hide）/ Escape / 点击菜单项，三路均隐藏窗口
- **关闭按钮**：主窗口 X 按设置页开关分流——开（默认）`plugin:window|hide` 隐藏到托盘；
  关则调 `exit_app` 直接退出（开关状态存 localStorage 键 `tauri-shell-tray-min`）
- **原生标题栏的 X**：用户自带 HTML 走原生标题栏时，Rust 侧拦截 `CloseRequested`
  → 隐藏进托盘（若不拦截，主窗口被销毁后隐藏的 tray-menu 窗口使进程不退、
  托盘又无法还原窗口，成为僵尸进程）
- **主题同步**：两窗口同源共享 localStorage，菜单页在渲染前同步读
  `tauri-shell-theme` 套 `data-theme` 防闪烁，每次获焦（即每次弹出）重读，无需事件广播

### 定制菜单项

改 `dist/tray-menu.html` 内 `.context-menu` 下的按钮即可（图标为内联 SVG，
Lucide 风格线性描边）。新增需要 Rust 能力的菜单项时，在 `lib.rs` 加对应
`#[tauri::command]` 并进 `generate_handler![...]`，前端 `invoke('命令名')` 调用。
保持扁平结构，不要做子菜单（会溢出小窗口）。

菜单尺寸无需手配：页面加载后按内容测量，一次性 `set_size`
（卡片 + 四周 16px 透明投影边距）。

### 易踩坑（改动前必读）

- **多窗口 `additionalBrowserArgs` 必须完全一致**：WebView2 同进程共享浏览器参数，
  任一窗口参数不同会导致后初始化的 WebView **静默创建失败**（窗口存在但页面空白、
  无任何报错）。给某窗口增删参数时，务必同步 `tauri.conf.json` 中所有窗口。
- **投影边距两侧一致**：`tray-menu.html` 的 `.shadow-pad` 内边距（16px）与
  `lib.rs` 的 `SHADOW_MARGIN`（16.0）必须相等，定位计算已计入该边距。
- **预建复用**：菜单窗口靠 show/hide 复用，切勿每次 create/destroy（白屏卡顿）。
- **显式退出**：挂托盘图标后销毁所有窗口进程也不退出，退出必须走 `exit_app`
  （`app.exit(0)`）；主窗口关闭按钮也因此不再用 `plugin:window|close`。
- **dev 服务器路由**：`serve -s`（SPA 模式）+ 默认 cleanUrls 会把
  `/tray-menu.html` 301 到 `/tray-menu` 再重写成 `index.html`，导致菜单窗口
  加载错页面。`dist/serve.json` 的 `"cleanUrls": false` 即为此而设，勿删。
- **DPI**：定位用物理像素 + `monitor_from_point` 夹取，窗口尺寸走逻辑像素，
  多显示器/非 100% 缩放下勿混用两种单位。

### 按需移除托盘

1. `src-tauri/Cargo.toml`：`tauri` 依赖去掉 `"tray-icon"` feature
2. `src-tauri/src/lib.rs`：删除「托盘」注释块（`exit_app` / `show_main_window` / `position_menu_window`）与 `.setup(...)` 中的托盘注册块（含主窗口 `CloseRequested` 拦截，否则窗口关不掉），`generate_handler![...]` 恢复为仅 `get_file_size` 与 `apply_window_chrome`
3. `src-tauri/tauri.conf.json`：删除 `app.windows` 中 `label` 为 `tray-menu` 的窗口
4. 删除 `src-tauri/capabilities/tray-menu.json`，并移除 `default.json` 中的 `core:window:allow-hide`（仅此一条与托盘相关；`allow-show` 与 `allow-set-decorations` 是自动边框机制所需，务必保留）
5. 删除 `dist/tray-menu.html`，`minify.cjs` 的 `PAGES` 数组去掉 `"tray-menu.html"`
6. `dist/index.html`：关闭按钮恢复为 `invoke('plugin:window|close')`，并删除设置页「窗口」卡片（`trayMinToggle`）及其脚本块「托盘：关闭按钮行为」
7. 可选：单实例插件 `tauri-plugin-single-instance` 无托盘时保留亦无碍（常规单实例保护仍有效）；需彻底移除则删 `src-tauri/Cargo.toml` 依赖，并删 `lib.rs` 中对应 `.plugin(...)` 注册块

> `dist/serve.json` 可保留（对无托盘项目无副作用），删除亦可。
